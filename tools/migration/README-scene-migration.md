# Starlight.SceneMigration

Standalone tool that turns pre-key-card documents into key cards that reference content-addressed assets in the engine asset library. Handles three document kinds: scenes (`.starscene`, schema below 16 or embedding sculpt/terrain geometry becomes schema 16), reusable objects (`.starobject`, Version 1 with an embedded Sculpt becomes Version 2; imported models are allowed) and reusable groups (`.stargroup`, same). The legacy reader lives only here; the engine runtime throws `ConversionRequired` on old documents.

Source: `scene_migration.cpp`. Target: `Starlight.SceneMigration` (links `starlight_editor_core`). The tool never opens a window and never runs a scene.

## Modes

- `--inventory <folder>... --out <inventory.json> [--no-extra-scan] [--extra-root <folder>...] [--inspect-outside]`: recursively lists `*.starscene`, `*.starobject` and `*.stargroup` (skips folders `out`, `publication`, `.git`, `node_modules` and any reparse point; `.bak`, `.tmp` and `.lock` files are never matched). Several roots are allowed; with more than one root each file's `stage_relative` starts with the root folder name (a second root with the same name becomes `name-2`), a file reachable from two roots is listed once, and a missing root is an error. Per file: path, kind, bytes, sha256, schema (Version for objects and groups), object count, embedded sculpt count and bytes, embedded terrain bytes, active model links, class and status. Writes `inventory.md` beside the JSON. Classes: `generated-check` (path contains `editor/checks/roundtrip/`), `audit-evidence` (`audit-runs/`), `authored` (everything else), `user-scene-outside-repo` (see below). Reports only.
  - Extra scan (on unless `--no-extra-scan`): `AppData/Local/Starlight`, `%STARLIGHT_DATA_ROOT%` when set, the Documents folder under the user profile (`C:\Users\<user>\Documents`) and the shell's Documents known folder (a different path when Documents is redirected), plus any `--extra-root`. Only the three extensions are listed. Those files are not opened (status `not opened (outside the repo)`, bytes only) unless `--inspect-outside` is given, they are never converted (`--convert-all` lists them as `outside repo (inventory only)`), and files inside an inventory root are not repeated. Each location's file count and any scan problem are recorded in `extra_locations`.
- `--convert <in> --library <dir> --archive <dir> --out <out> [--relative <name>] [--in-place] [--source-library <dir>...]`: converts one document (kind from the extension).
- `--convert-all <inventory.json> --library <dir> --archive <dir> --stage <dir> [--source-library <dir>...]`: converts every `authored` and `audit-evidence` entry into `<stage>` mirroring relative paths. `generated-check` entries are listed as `regenerate`; `user-scene-outside-repo` entries are listed and left alone. Documents already at the key-card version are copied into the stage and verified like converted ones, and reported `already key card` per file (the summary says whether the copy is byte for byte). Writes `conversion-summary.json` and `.md` into the stage folder, including a warnings section and every document's model imports.
- `--verify <file> [--library <dir>]`: decodes with the engine, re-encodes and requires identical text, checks that every referenced asset file (sculpt, terrain and model) exists and hashes to its id (read straight from disk, not from the engine's memory cache) and, for scenes, that every model used by a non-shape, non-sculpt object loads and parses from the library. `--library` is required for scenes; objects and groups are checked against the `assets` folder beside the file only.
- `--verify-all <stage dir> --library <dir> --out <verify.json>`: verifies every document under the stage; writes `verify.json` and `verify.md`.

Exit codes: 0 success, 1 a conversion or verification FAIL, 2 usage error or refusal.

## Conversion steps

1. The original is copied to `<archive>/files/<relative name>` and `{path, archive, sha256, bytes}` is appended to `<archive>/manifest.json`. An existing archive entry or file with a different hash aborts the conversion; the archive is never overwritten. Legacy documents are always archived; an already-key-card document is archived only when the staged text differs from it.
2. Legacy sculpt and terrain arrays are read from the JSON, validated with the engine's own `validate()`, and stored with `store_sculpt` and `store_terrain_geometry`. Identical geometry dedupes by id. An already-key-card document's referenced assets are copied (verified) into `--library` from the default library roots (the `STARLIGHT_ASSET_LIBRARY` override alone, otherwise the roots registered in the Starlight data folder's `asset-roots.json` and the local `AssetLibrary`; see `EngineAssets::default_roots`), from any `--source-library`, and from the `assets` folder beside the document and the shipped engine library found by `discover_near`; a missing source asset is a FAIL.
3. Geometry is replaced by `{"Asset": id}` references and the version is raised (scene `SchemaVersion` 16, object and group `Version` 2); every other field is kept.
4. Model links (scenes, reusable objects and reusable groups): every non-empty `Character.Asset` that is a file path (absolute as written, relative to the input document's folder) is imported into the library with the same `import_model` the editor and command line use (GLB validated with the engine's parser and the embedded-resource rule, stored once as `model-<sha256>`), and the document keeps only the model id. The stored copy is compared with the source file byte for byte. Identical GLBs dedupe to one id across all documents. A model file that cannot be found makes the whole document FAIL, with every missing path listed in the error; nothing is converted and nothing is dropped silently. A GLB that exists but is not a valid model also FAILs. Links on objects that also have a built-in shape or sculpt are ignored by the engine: in a scene they are imported when the file imports, otherwise (and always in reusable objects and groups, whose encoder clears them) they are cleared with a warning; the original is archived. A schema 16 scene or Version 2 object that still holds a path in `Asset` (made by an earlier build) is treated as legacy: archived, imported and rewritten. Documents that already hold model ids have those models copied (verified) from the default, source or bundle libraries like any other referenced asset.
5. Verification before anything is written: each stored asset is re-read from disk and its identity recomputed; the engine decodes the new text (`SceneData::decode`, `decode_object_template`, `decode_object_group`); every decoded sculpt and terrain equals the legacy arrays bit for bit; the engine's re-encoded text is stable under decode and re-encode; every field of the original that is not geometry must be present and equal in what the engine reads back. Fields the engine adds with defaults are listed separately (`defaults_added`); any dropped or changed field is a FAIL and the output is not written. Reusable objects have their `Id` cleared and group members are renumbered `member-N` by the engine's own encoder; the report counts these as `ids_normalized` (links such as `JointTargetId` are renumbered with them).
6. The output is the engine's own encoded text (so `--verify` stability holds), written with `atomic_write`. For objects and groups the referenced assets are first bundled with `EngineAssets::bundle_into` into an `assets` folder beside the staged file (the layout `save_object_template` and `save_object_group` produce); object and group files in the same folder share that folder. The written file is read back and then verified again from its final location (scene: against the library; object and group: against the bundle only, with the assets read from disk). `<out>.migration-report.json` records original and new sha256, asset ids (sculpt, terrain and model), sizes, defaults added, real differences, models (object, original path, resolved path, model id, action), warnings and result.

The input path is never written unless `--in-place` is given; the archive entry is written and verified first in every conversion, so in-place always has a verified archived original.

## Notes

- `atomic_write` (platform.cpp) creates a zero-byte `<file>.lock` beside every file it writes and does not delete it. The tool cannot change that, so after each run it deletes zero-byte `*.lock` files whose guarded file exists, in the library, the archive, the stage tree, the output folder and the inventory folder. Deleting a lock that is currently held by a writer fails harmlessly (the lock is opened with no sharing), so this never interferes with a concurrent writer; a held lock is simply left. The fix at the source would be opening the lock with `FILE_FLAG_DELETE_ON_CLOSE` in `atomic_write`.
- Scenes whose geometry is bit-identical share one library asset; `conversion-summary.json` lists every asset with its documents and reference count.
- Generated checks (`editor/checks/roundtrip/`) are not analyzed for model links; they are regenerated, not converted.
- Schema above 16 (documents above Version 2) is refused.
- The imported models live in `--library`, not beside the staged scene; an exported game bundles the dependency closure from there.
