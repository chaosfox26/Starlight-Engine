# Object-first authoring requirements

User direction24 September2026: place/move a block in the room, then right-click it or press F near it to open simple contextual choices. Organize choices into movement, pickup, break, open and similar categories. Selecting a behavior should connect real object behavior with an optional ordered quest objective. Do not require users to manually assemble rule IDs or navigate a large global rule form for this simple workflow. This extends Step3's authoring scope; not implemented yet. Keep existing advanced rules available.

Starlight proposal: place/select -> object menu -> category -> behavior -> optional Add quest step / choose existing quest -> preview ordered steps -> Play. Label physical pickup/carry separately from collect-into-inventory; label landing on top separately from a generic nearby-area event. Break must have actual break/destruction behavior; opening must target the selected/link object. Unsupported behavior must not appear functional. Selection, menu focus, Undo, saved stable links and exported behavior must agree. Right-drag already controls camera; preserve that by distinguishing context click from drag or use F as the primary object-options shortcut. Do not silently repurpose E gameplay use.


24 September clarification: F is the primary in-world object-menu key. Creation lessons follow the exact placed object, e.g. choose/place cube, F, assign Open or Breakable, then test. A quest step contains1–5 objectives that complete in any order; completed text becomes green and struck through. All objectives finish before the next step. Quest rewards/EXP and lesson prerequisites (possibly two quests) belong to Task6 and must not gate routine/advanced creation. User includes F authoring in expanded Task3. Presets must execute real behavior, not only change labels.
