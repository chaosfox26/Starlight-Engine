## Integration findings before further implementation

1. The existing native harness already covers most runtime stages. Reuse it; do not build a duplicate suite. CTest registration and harness stages overlap, especially UI/session checks. A combined pass should avoid redundant executions unless their conditions differ.
2. Seven registered CTest names: audit-contract, native-core, native-diagnostics, native-no-managed, native-textures, native-classic-ui, native-session. Visible rendering, visible editor walkthrough, handle controls, denoiser capture and fallback matrix are additional coverage, not implied by those seven.
3. The native audit executable is built under Release/audit/, not directly under Release/. The unfinished coordinator currently assumes the wrong path. Its --extra-evidence argument is not yet supported by deep_analysis.py. These are implementation gaps, not a validated integration.
4. Fixed-output tools need output redirection or evidence preservation before repeatable orchestration; fresh wrapper logs alone do not preserve their raw results.
5. Specialized denoiser/fallback tools need current binary paths and explicit workload labels. Small offscreen diagnostic passes must never become fullscreen performance claims.
6. Feature-evidence linkage is implemented, but legacy records and unmapped test families stay review-required. Every producer needs truthful execution-time source/build/workload provenance; no retroactive hashes.
7. The desktop Start workflow compiles, but repeated live execution is not yet verified. Feature/error/combined action selection is not wired. Batch-mode native harness changes also require a build and validation.
8. A standalone shareable report needs current feature state, runtime failures, not-run coverage, GUI state, known issues and proposed scope. Inventory counts and source matches cannot establish semantic correctness or visual acceptance.
9. Keep source-mutating migration/retirement/document-patching utilities outside any automatic audit execution list.
10. Fullscreen FPS/GPU/native-resolution readout remains queued; this tool inventory is the current priority.
